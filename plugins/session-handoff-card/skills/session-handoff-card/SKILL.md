# 通用会话交接卡

生成精简的 UTF-8 Markdown 接手文件。交接卡是上下文控制与证据导航，不是
聊天复刻，也不替代项目文件、日志、测试或实时状态。

## 选择模式

- **写出**：当前会话准备暂停或换模型。
- **接收**：新会话审计并继续已有卡片。
- **更新**：状态发生实质变化后刷新同一张活动卡。

若会话很短、没有要求覆盖/失败路线/权限边界/外部证据，且只需转述一两个事实，
直接写普通中文摘要，不强制生成交接卡。交接卡用于“摘要遗漏会让工作走错”的场景，
不是每段聊天的固定仪式。

默认写出直接使用本文件和模板。状态为 `PARTIAL/BLOCKED/WAITING`、证据或
覆盖语义有歧义时再读 `references/handoff-protocol.md`。只有历史无法一次
读完或完整性不确定时才读 `references/long-context-reconstruction.md`；
跨机器、附件或纯文本交接时读 `references/model-compatibility.md`。

## 写出

1. 盘点当前可见聊天、历史导出、项目指令、实际文件、日志、测试和用户补充。
2. 按顺序处理全部已提供历史。无法完整取得时必须标成 `PARTIAL` 或
   `UNAVAILABLE`，不得用抽样冒充 `FULL`。
3. 合并最新有效要求，显式保留被覆盖要求、失败且不应重试的路线、授权边界
   和上下文缺口。聊天只能证明“说过什么”，项目状态必须对照证据核验。
4. 使用 `assets/handoff-card-template.md`，直接写四节核心卡。不要输出逐项
   覆盖矩阵、重复状态章节或聊天复刻。普通卡目标为 1500–3500 字符；只有
   高风险复杂任务才可接近 8000 字符。默认只列 3–6 条会改变接手决定的高影响
   证据；不要为每个文件都抄摘要或计算哈希，除非跨机器校验、防篡改或用户要求。
   卡片接近或长于原始历史时应继续压缩，把低频时间线和完整清单外置。
   原始历史是覆盖审计材料，不是默认接手附件；只有覆盖不全、冲突、关键证据
   缺失或用户要求审计时才随卡提供。首条提示词只点名 1–3 项最需复核的可变证据，
   不要求接收方重读整张证据表或全部历史。
5. 历史需要分块时运行：

   ```text
   python scripts/chunk_history.py --input <历史导出> --output-dir <分块目录>
   python scripts/verify_history.py --source <历史导出> --index <分块目录/history-index.tsv>
   ```

   写出方必须读完所有分块；接收方默认不必重读原历史。
6. 创建草稿可运行：

   ```text
   python scripts/new_handoff.py --output <交接卡> --project-root <项目根目录>
   ```

7. 完成后严格校验：

   ```text
   python scripts/validate_handoff.py <交接卡> --strict --check-paths
   python scripts/validate_handoff.py <交接卡> --strict --check-paths --source-history <历史导出>
   ```

8. 返回卡片路径、状态、历史覆盖、校验结果和最小附件清单。

## 接收

1. 先读完整交接卡，再读最高影响的当前证据；不要一开始重读全部旧历史。
2. 运行校验器，重新检查会变化的 Git、文件、测试、进程、外部任务和界面。
3. 分类：
   - `VERIFIED`：核心上下文和实时证据仍一致；
   - `STALE`：状态已变化，先更新卡；
   - `BLOCKED`：缺历史、证据、访问、授权或必要输入。
4. 用中文报告当前目标、失效要求、已核验证据、缺口、唯一下一动作和停止条件。
5. 只有以下情况才升级读取历史索引或原始分块：卡片校验失败、覆盖为
   `PARTIAL/UNAVAILABLE`、要求发生冲突、高影响证据缺失、用户要求审计，或
   卡片无法解释关键决定。
6. 仅执行唯一下一动作；需要新权限时停止并询问用户。

## 更新

保留旧决定和失败记录，刷新 `updated_at`、状态、证据、阻塞、下一动作和更新
日志。将失效项标为 `SUPERSEDED`，不得留下两个有效下一动作。重新严格校验。

## 不可违背

- 面向人的文字优先中文；状态码、路径和命令保持原样。
- 不记录思维链，只记录可恢复工作的结论、依据和决定。
- 不把卡片的结构通过当成事实验证通过。
- 不写入密钥、令牌或直接个人敏感信息。
- 不扩大用户授权，不静默解除阻塞或停止条件。
