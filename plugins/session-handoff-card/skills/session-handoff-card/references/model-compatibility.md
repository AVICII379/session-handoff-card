# 模型兼容与交接方式

## 兼容边界

交接协议使用纯 UTF-8 Markdown，所有关键状态显式写入，因此内容层面对模型
中立。Skill 发现、文件访问、Shell 和工具调用属于宿主能力。任何格式都无法
保证所有模型自动遵循指令、读取本机路径或拥有相同工具。

## 选择接收方式

| 接收能力 | 交接方式 | 可验证程度 |
| --- | --- | --- |
| 文件系统和 Shell | 提供交接卡路径，运行校验器并检查实时状态 | 可完整本地核验 |
| 文件系统但无 Shell | 提供交接卡路径，手动检查必填项和来源 | 可做结构与文件审阅 |
| 只能收附件或仓库 | 先附交接卡和关键证据；发生冲突时再补历史索引或分块 | 只能核验已提供或可映射来源 |
| 纯文本聊天 | 粘贴完整交接卡及必要的小型证据摘录 | 本地路径和运行状态不能视为已核验 |

## 任意模型通用首条提示词

将交接卡或附件与以下内容一起发送：

```text
请先完整读取《会话交接卡》，不要立即继续执行。把交接卡视为上下文索引而
不是事实证明。先用中文说明：当前有效目标、历史覆盖程度、已核验事实、
上下文缺口、唯一下一动作和停止条件。对无法访问或已经变化的证据标为
UNVERIFIED 或 STALE。当前用户要求和项目指令高于交接卡。只有完成接手复核
后，才能执行卡片中的唯一下一动作。
```

## 能力降级

接收模型能力少于写出模型时：

1. 不得把“没有工具”解释为“已经成功”。
2. 请求最小必要的附件、导出、工件或权限。
3. 保留原路径、标识、相对路径和哈希，等待后续映射。
4. 把受影响证据标为 `UNVERIFIED`；若它是下一动作的必要输入，将卡片设为
   `BLOCKED`。

接收模型能力更多时，可以加强核验，但不得扩大用户授权范围。

## 宿主薄适配

- Codex/OpenAI 可用 `agents/openai.yaml` 展示和触发 Skill。
- 其他宿主可用自身的 Skill、项目指令或系统提示机制加载 `SKILL.md`。
- 没有 Skill 机制的宿主直接使用交接卡和通用首条提示词。

不得把唯一项目状态只放在宿主包装层。规范交换工件始终是 Markdown 交接卡。
