# 可用性自测与 A/B 复盘

日期：2026-07-19
版本：插件 0.3.0，协议 `session-handoff-card/v1.2`

## 目的

这次测试不以“模板能通过校验”为成功，而是检查两个问题：

1. 写出方能否在长历史中恢复最新有效要求，而不复活旧路线；
2. 没看过旧会话的接收方，能否只靠交接内容和少量证据安全继续工作。

测试夹具是 30 条相互覆盖、包含失败路线和权限收紧的会话，共 3662 个字符。
对应 mock 项目包含当前规范、实现、6 项测试、旧测试报告和失败路线日志。隐藏
评分真值规定唯一下一步只能是“只读审计并提交碰撞函数修改计划，随后等待确认”。

## A/B 方法

- 普通摘要组：写出方只能读历史和项目，不得读取 Skill、模板或评分真值，自由写摘要；
  接收方只读摘要和摘要明确引用的证据。
- 交接卡组：写出方读取 Skill 和相同历史、项目，不得读取评分真值；接收方只读
  交接卡和最高影响证据，除非触发升级条件，否则不得读取原历史。
- 两组均禁止修改 mock 项目，接收方必须报告目标、失效路线、证据缺口、唯一
  下一步和停止条件。

## 结果

| 条件 | 产物 | 结果 | 暴露的问题 |
| --- | ---: | --- | --- |
| 普通摘要 | 1655 字符，30 行 | 接收方正确恢复目标、全部禁用路线、碰撞规则、两项测试和“获批前不编辑” | 在这个中等规模夹具上已经足够好；没有覆盖状态、结构校验和跨机器降级约定 |
| v0.2 旧核心 | `SKILL.md` 7561 bytes，模板 5033 bytes，协议 5675 bytes | 两次全新写出尝试在数分钟内未产生产物；旧演示卡 11817 bytes，而源历史 4310 bytes | 12 节和约 40 个必填项造成写卡瘫痪；演示只是预填正确卡再换路径，不能证明模型会写 |
| v1.2 首次精简 | 5084 字符，9 条证据，源历史比 1.388 | 写出和盲接均成功；接收方安全恢复任务并未修改文件 | 卡片仍重复边界和下一步，逐文件哈希过多；`READY` 易被误读为项目完成 |
| v1.2 预算版 | 2618 字符，4 条证据，源历史比 0.715 | `HANDOFF_READY/FULL`；严格路径与压缩比校验 0 错误、0 警告；最终接收方被禁止读取原历史，仍准确恢复目标、优先级、两项测试、失效路线和停止条件；项目未改动 | 首次产物仍把原历史列入默认附件，说明“渐进审计”还需在模板中写得更硬；随后已改成“最小接手附件”并重新校验 |

写出耗时受模型调度和推理风格影响，不能单独当成质量指标。因此本轮主要采用
产物长度、证据数量、压缩比、语义命中和是否越权作为判据。

最终盲接只留下一个领域层面的实施前问题：`detect_name_collisions()` 是自己调用
`mark_duplicates()`，还是由调用方保证执行顺序。接收方没有把这个未决点擅自
补成事实，也没有因此越过“只给计划”的授权。

## 自我反省

旧设计最大的问题是把“审计完整”误写成“卡片必须装下所有东西”。这会产生五个
反效果：

1. 写卡者花大量精力填表，而不是判断哪些状态真正影响接手；
2. 同一个目标、状态、下一步和停止条件在多个章节重复；
3. 接收方又被要求重读卡片、索引、证据和全部历史，失去压缩价值；
4. 每个文件都加摘要和哈希，制造形式上的可信感；
5. 结构通过被误当成语义正确，预填演示形成自证循环。

普通摘要组表现很好，说明 Skill 的价值不能建立在“普通摘要一定失败”这个假设上。
短会话或低风险单事实交接，普通摘要更省力。交接卡只应服务于遗漏上下文会导致
走错路线、越权或误判项目状态的场景。

## 本轮保留与删除

保留：

- `FULL / PARTIAL / UNAVAILABLE` 的诚实历史覆盖；
- 最新有效要求、失效路线、用户边界和停止条件；
- 证据来源、状态和最后核验时间；
- 恰好一个下一动作；
- 接收方先复核可变证据、冲突时才升级读取历史；
- 标准库分块、精确覆盖和结构校验脚本。

删除或收紧：

- 12 节卡片改为 4 节；
- 删除逐项覆盖矩阵、重复状态章和聊天复刻；
- 普通卡目标 1500–3500 字符，5000 字符以上警告；
- 证据默认 3–6 条，超过 6 条警告；
- 哈希仅用于跨机器、防篡改或用户明确要求；
- `READY` 改为 `HANDOFF_READY`；
- 原历史不再是默认接手附件，首条提示词只点名 1–3 项最需复核的可变证据；
- 新增相对源历史的压缩比警告，但不把压缩率当成正确性分数。

## 可复现检查

```powershell
$env:PYTHONUTF8 = "1"
python .\examples\run_demo.py
python -m unittest discover -s tests -v
```

压力卡校验示例：

```powershell
python .\plugins\session-handoff-card\skills\session-handoff-card\scripts\validate_handoff.py `
  <handoff.md> --strict --check-paths `
  --source-history .\tests\fixtures\ab-session.md --json
```

行为 A/B 需要两个没有共享聊天记忆的新模型实例；评分时必须禁止写出方和接收方
读取 `tests/fixtures/ab-ground-truth.json`。机械演示只能证明脚本和结构，不能替代
这项盲接测试。

## 仍未解决的边界

- 校验器能发现结构、路径、长度、证据数量和常见凭据问题，不能证明模型的语义
  摘要一定正确。
- `FULL` 只表示已提供给写出方的历史被全部处理，不能证明宿主没有提前截断。
- “适配所有大模型”只指 UTF-8 Markdown 协议模型中立，不保证所有宿主具备相同
  文件、Shell、Skill 自动发现或工具能力。
- 很短的历史可能因固定元数据而出现压缩比大于 1；这种场景通常应直接用普通摘要。

## v0.4.0 追加试用：轻量、大众与无插件路径

日期：2026-07-26。写出者与接收者均使用新的无共享对话实例，只允许读取各自指定的源会话
或交接产物，不允许读取 `benchmarks/ground-truth`。临时产物保存在被 Git 忽略的
`.ab-eval/v040`，不进入发布包。

| 条件 | 结果 | 发现与处理 |
| --- | --- | --- |
| 不使用 Skill 的普通摘要 | 359 字符；写出准确保留预算、饮食、体力、授权、废弃路线、下一步和停止条件 | 普通摘要在简单规划夹具上仍然很好；盲接方却新增了源文件不存在的“编码乱码”缺口和未明确授权的额外限制，证明自由结构较难区分原文与接收方推断 |
| QUICK v1 | 1167 字符；严格校验通过，隐私预览无发现 | 接收方正确区分对话证据与外部事实，但看到日期、出发地等缺口后擅自把唯一下一动作改成追问，暴露“列出缺口”不等于“说明缺口影响” |
| QUICK v2 | 1509 字符，其中正文 1146；严格校验与隐私预览均通过 | 模板和校验器改为强制每个缺口标明“阻塞/不阻塞”；修订后盲接准确保留生成两个候选方案的唯一动作，没有改成追问 |
| 无插件通用提示词 v1 | 语义内容正确，但首轮发明 `READY`、`COMPLETE_PROVIDED_HISTORY`、无编号标题和 `project_path` | 仅口述字段不足以形成跨模型协议；校验器增加未知字段拒绝，提示词改成可照抄的完整骨架 |
| 无插件通用提示词 v2 | 1469 字符，其中正文 1078；首轮严格校验通过 | 证明未安装 Skill 时，完整骨架比“字段说明”可靠；仍只代表本次模型试用，不代表所有模型都必然遵循 |
| 英文 VERIFIED | 3498 字符、3 条 `USER-PROVIDED` 证据、严格校验通过 | 盲接方正确声明没有外部证据，把“一个 lineage 已验证”降为接收方未核验，并保留 ID 对齐门和禁止路线 |

这轮对比改变了两个设计判断。第一，QUICK 的价值不是“比普通摘要更会复述”，而是提供
覆盖、证据层级、授权与停止条件的稳定槽位；极简单任务仍可直接摘要。第二，缺口必须携带
控制语义：除非卡片明确 `BLOCKED` 或写明“阻塞唯一下一动作”，接收方不能因为想获得更
完整信息就替换下一动作。

试用环境有一个隔离限制：机器策略要求每个代理启动时调用本地记忆系统，其中一次对照写出
明确报告启动包自动返回过历史摘录。所有代理均被禁止主动读取标准答案，产物也未显示命中
其他项目事实，但这不是实验室级的绝对零上下文。因此这些结果用于发现产品问题和回归，
不应包装成跨模型统计结论。
